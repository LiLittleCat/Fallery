# 验证

## 语言检查

`dotnet run --project Tests/LanguageChecks/LanguageChecks.csproj -- .` 校验中英文资源覆盖、代码/XAML 引用、格式占位符、语言切换及取消时的多窗口冲突。CI 和本地发版检查已包含该项目。

隐藏窗口检查：构建 ExperienceChecks 后，以 `FALLERY_LANGUAGE_CHECKS=1` 运行。检查现有窗口/菜单/设置面板即时更新、视图与播放状态保持、语言持久化、回收控件不把文件名当作文案；使用隔离设置和静音播放器替身，不发送键鼠。

该检查还会先执行 GC，再核对背景说明、缩略图标题和关联标题的英文文案，比较切换前后的设置内容宽度，并确认丢弃的本地化控件可以回收；防止只测试刚创建的控件而漏掉原生树仍持有控件、托管包装已释放的情况。

人工检查：设置中选择 English，应立即更新当前及其他窗口；切回中文或取消设置验证回退。播放中切换语言应保持进度/音量，文件名和路径保持原样。完成后退出全部窗口并重开，确认语言恢复；检查英文按钮和菜单没有截断。系统提供的对话框/元数据仍可能使用系统语言。

## 安装和更新流程

`./Tests/ReleaseChecks.ps1` 检查 Changelog 的当前项目版本、单版本提取、链接保留，以及缺失/重复/空版本条目的拒绝行为；CI 和发版工作流均运行此检查。

构建、发版与数据目录见 [DEPLOYMENT.md](../DEPLOYMENT.md)。普通构建默认 dev，真实用户数据改用 `%LOCALAPPDATA%\Fallery.Dev`，旧的 `%LOCALAPPDATA%\Fallery` 留给正式安装版。

```powershell
dotnet run --project Tests/UpdateChecks/UpdateChecks.csproj
dotnet build Tests/ExperienceChecks/ExperienceChecks.csproj -p:Platform=x64
$env:FALLERY_UPDATE_CHECKS = '1'
Start-Process -FilePath './Tests/ExperienceChecks/bin/x64/Debug/net10.0-windows10.0.22621.0/win-x64/ExperienceChecks.exe' -WindowStyle Hidden -Wait
Remove-Item Env:FALLERY_UPDATE_CHECKS
Get-Content './Tests/ExperienceChecks/bin/x64/Debug/net10.0-windows10.0.22621.0/win-x64/experience-checks.txt'
```

更新检查使用隔离临时包和 SDK TestVelopackLocator，覆盖取消/重试、并发、保存失败、重启顺序、产品/通道/降级与坏包校验；不执行安装器或替换实际程序。隐藏宿主直接检查生产设置面板和保存接线，不注入输入，假播放器保持静音。

必须人工验收：安装两个递增版本，从“设置 → 版本与更新”检查、下载、确认重启，验证多窗口关闭及设置/续播保留；取消和断网可重试；卸载取消关联但保留数据。私有仓库的客户端匿名请求预期失败，不能把它当作“已是最新”；公开仓库并发布完整 Release 后再验收在线通道。

## 横排缩略图完整边界

- 在“大图 + 底部缩略图”模式切换显示文件名和卡片背景，缩略图底边、文件名、选中边框应完整。
- 鼠标移到水平滚动条使其展开，再横向滚动，滚动条不应盖住卡片底部；切回其他视图应恢复原来的留白。

## 文件树创建时间排序

- 点击文件树上方齿轮，选择“创建时间”，切换升序/降序；关闭日期显示后排序仍应有效。
- 当前选中目录与展开的子目录应保留，右侧媒体排序不受影响；重启后应恢复创建时间排序及方向。

## 多窗口与列表视图

- 在“视图”选择“新建窗口”或按 Ctrl+N；文件夹右键也可“在新窗口中打开”。重复运行 exe/从资源管理器打开应新开窗口，保留原窗口的目录、选择与播放。关闭最先打开的窗口后，其他窗口仍能导航和新开窗口。
- “视图 → 列表视图”：小预览、名称、类型、大小、创建时间、修改时间每行展示；点击名称/大小/日期列头切换排序方向。目录大小显示“—”，不递归扫描统计。
- 缩窄窗口后横向滚动，列头必须跟随；纵向滚动时表头固定。测试 Ctrl/Shift 多选、方向键、双击/空格打开、Esc 返回、右键操作，切回原视图不能残留列宽或表头。
- 自动检查使用静音、未激活的生产窗口，不向用户窗口发送输入；真实外观和操作仍需人工验收。

## 调整窗口时的预览复用

- 等图片、视频和文件夹叠图加载完成，反复拖动窗口边缘、最大化/还原，或调整左侧文件树宽度：已在缓存中的预览应直接重现；更大尺寸加载期间保留旧图。
- 修改/删除文件夹内的封面文件后，等待自动刷新或按 F5；旧封面应更新。切到其他目录再回来也应重新验证。
- 隐藏生产窗口的 ResizePreviewChecks 覆盖真实卡片回收后的同步复用；TileChecks 覆盖预览尺寸升级、模型引用释放及导航后重新验证。外观仍需人工验收。

在项目根目录运行（Windows、.NET 10，无额外测试包）：

```powershell
dotnet run --project Tests/CoreChecks/CoreChecks.csproj -- .
dotnet build -p:Platform=x64
```

检查实际扫描代码的自然排序、扩展名和隐藏文件过滤、取消及失败语义；用一万项混合宽高比检查布局边界、重叠、滚动范围，并将可见项查询与完整遍历结果对照。测试素材生成在忽略的 `work/validation/corechecks/` 中。

如果存在 `work/validation/media`，还会检查实际 Windows 解码器的图片宽高比、系统缩略图、MP4/MOV 元数据、损坏文件与取消行为。

这些检查不替代界面验收。运行 Fallery 后还需检查：

1. “打开文件夹”或 Ctrl+O 打开 `work/validation/media`，检查数量、面包屑、返回和上级。
2. 快速切换目录，或打开后删除/拔出测试目录，确认旧扫描不会覆盖当前目录，失败后仍能重新打开。
3. 打开 `work/validation/large`，连续滚动和调整列宽，观察内存是否趋于稳定，而非随浏览数量持续增长。
4. 连续快速切图（包括 A→B→A），加载中按 Esc，再重新打开，确认没有旧图片闪回或关闭后继续播放。
5. 打开 GIF、图片和 MP4/MOV，检查缩放、平移、播放、全屏、切换、关闭和损坏文件提示。
6. 将焦点移到主题下拉框和播放滑块，检查方向键没有被查看器抢走。
7. 通过“打开文件夹”选择尚未展开的深层目录，检查左侧展开、高亮及滚动定位；后退、上级和面包屑跳转后选中项应与当前目录一致，快速切换不会被旧定位覆盖。
8. 打开 `work/validation/folders`，检查“图片”“视频”“混合”“空文件夹”卡片及封面，双击进入，再用上级返回。“混合”包含一个子文件夹、一个 JPG 和一个 MP4；查看器应只显示两项媒体，左右键不能进入文件夹。
9. 图片首次打开、窗口调整大小、F11 进出全屏后应居中；关闭查看器应恢复原窗口状态。
10. 顶部“视图”依次切换瀑布流、大图列表、大图 + 底部缩略图；切换不应重扫目录，隐藏文件名应去掉标题空行，重启应恢复模式和开关。
11. 横排模式点击缩略图及左右键切换图片/视频，确认下方选中同步且自动滚到可见位置；进入空目录或输入失效路径，不能残留其他目录的图。F11/Esc 进出全屏，普通预览中 Esc 返回瀑布流。
12. 在文件树、缩略图和大图右键，检查打开/展开/折叠/刷新、资源管理器定位、复制路径与复制文件后粘贴；右键拖动执行导航时不应同时弹菜单。上述外部应用和剪贴板操作未由隐藏测试自动执行。
13. 打开 `work/validation/folder-stacks`，主浏览区只显示两个有媒体的相册，包含多层目录的相册也有叠放预览；无媒体分支隐藏。检查隐藏文件名后仍有文件夹角标，切换目录及滚动后叠层不残留；在深层添加或删除最后一个媒体后，回到父级 F5 应重新判断。
14. 顶部排序切换拍摄/创建/修改日期、名称/大小及升降序；筛选切换所有媒体/图片/视频和子文件夹显示，查看叠放封面和播放列表是否同步。右上角齿轮修改主题、视图、文件名和缩略图大小，分别验证保存、取消及正常关闭后的恢复。拍摄日期后台检查会在隔离 JPEG 副本中写入 EXIF 并验证排序与覆盖失效，不修改用户媒体。

按用户要求，不使用 Computer Use。构建并启动后提供上述步骤，由用户确认视觉和交互结果。后台检查额外覆盖文件夹优先排序、空/失效目录、封面候选限量、非递归和取消；它们不能替代卡片封面及双击的实测。

卡片复用回归测试（复用项目现有 WinUI/MVVM 依赖，直接实例化生产控件，不模拟输入）：

dotnet build Tests/TileChecks/TileChecks.csproj -p:Platform=x64

测试连续将同一控件换绑为图片、视频、文件夹及空对象，验证名称、提示路径、角标、封面与旧通知隔离。导航仍需人工检查：测试目录 → 自己的其他目录 → 空目录 → 后退，确认“混合”等旧名称不残留，点击目标与显示一致。

## 资源管理器右键与安装器接入

便携版可在设置点击“注册右键菜单与打开方式”。安装版必须部署完整自包含目录，并在安装、升级或修复完成后同步执行：

```powershell
$registration = Start-Process -FilePath "$installDir\Fallery.exe" -ArgumentList '--register-shell' -WindowStyle Hidden -Wait -PassThru
if ($registration.ExitCode -ne 0) { throw "注册失败：$($registration.ExitCode)" }
```

卸载时，在删除程序文件之前同样等待执行 `--unregister-shell` 并检查退出码。两条命令不启动界面、不向已开窗口转发；0 成功、1 操作失败、2 参数组合错误。安装器需要以目标用户身份运行（HKCU），不能以 SYSTEM 或另一管理员身份代注册。程序迁移位置后重新注册；旧位置卸载不会移除新位置注册。取消注册只移除 Fallery 的关联/右键入口，不清除用户设置、索引、缩略图或其他应用的菜单。

人工验收：右键支持的图片/视频、普通文件夹、文件夹内空白处及磁盘，检查“用 Fallery 打开”和图标；覆盖含中文/空格路径、磁盘根目录，检查冷启动和已有实例均打开正确目标。文件仍可从“打开方式”选择 Fallery，原默认应用保持不变。取消注册后入口消失，再次注册可恢复。

当前非打包静态菜单在 Win11 的“显示更多选项”中。未来若采用 MSIX，需用清单文件关联和 Shell 扩展声明；Win11 一级菜单还需实现 IExplorerCommand 和应用身份，不应宣称现有静态注册已覆盖。[微软集成说明](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)

核心检查使用独立的临时注册表子键，覆盖注册、缺失项检测、路径迁移、旧位置卸载保护、重复卸载、保留默认应用和其他入口，不修改正式关联。

## WebP 大图与详情回归

核心检查使用自生成纯色 WebP（包括改成 JPG 后缀的副本）验证原始 EXIF 查询按实际解码器限定为 JPEG/TIFF，同时检查 WebP 尺寸、缺失字段及原 JPEG 镜头信息。不会复制用户照片到仓库。

诊断某个实际图片时，构建 ExperienceChecks 后，仅在启动测试进程的环境中设置 `FALLERY_IMAGE_SAMPLE` 为其完整路径。宿主读取尺寸和详情，并在隐藏生产窗口中打开、布局、关闭三次，将结果写入 exe 同目录 `experience-checks.txt`，随后退出；正常全套检查不设置该变量。外层启动脚本须设进程超时（如 30 秒）并清理自己的测试进程，因为原生接口卡住 UI 线程时托管超时无法中断它。

人工验收：双击曾崩溃的 WebP，打开详情、放大、切换到相邻图片，再按 Esc 返回；确认显示、缩放和返回都正常。隐藏检查不替代实际显示与键鼠交互验收。

## 视频侧键手势回归

边界回归：构建 ExperienceChecks 后设置 `FALLERY_SEEK_BOUNDARY_CHECKS=1` 启动隐藏宿主；`FALLERY_SEEK_SAMPLE` 可指定实际视频。覆盖恢复播放回调中的紧接定位、系统时钟临时暂停时仍保留播放意图、点击和快退到开头、点击和快进到结尾后实际打开下一项、暂停定位及最后一项重播。使用两个无版本信息的播放项，避免写入用户续播记录；静音/零音量，不发送键鼠输入。原生时钟暂停仅用于构造竞态，不代表用户 Pause。

同一检查还模拟时钟超过总长且永不发送 Ended 的播放器，要求计时器兜底打开真实的下一段视频；迟到的旧播放器结束通知不得重复推进。另验证自然播放到结尾的正常连播。

任务栏与查看器菜单专项：构建 ExperienceChecks 后设置 `FALLERY_VIEWER_SHELL_CHECKS=1` 启动隐藏宿主；使用静音假播放器，调用真实 ITaskbarList3 检查进度/暂停/恢复/清除，并检查图片与视频菜单仅针对当前文件、浏览区继续支持多选。检查后自动关闭宿主；不打开菜单、不执行复制/删除、不发送用户输入。任务栏实际显示和右键事件路由仍需人工验收。系统状态定义见 [ITaskbarList3::SetProgressState](https://learn.microsoft.com/windows/win32/api/shobjidl_core/nf-shobjidl_core-itaskbarlist3-setprogressstate)。

单次跳转耗时诊断：`dotnet run --project Tests/CoreChecks/CoreChecks.csproj -- . --seek-sample <视频完整路径>`，直接使用静音系统播放器，报告 Position 提交与 SeekCompleted 耗时；`FALLERY_SEEK_REALTIME=1` 开启对照低延迟模式，`FALLERY_SEEK_PLAYING=1` 在播放状态测量。支持暂停状态的默认测量；计时仅用于本机对照，不设跨机器性能断言，也不测屏幕首帧。

设置 `FALLERY_PLAYBACK_CHECKS=1` 启动 ExperienceChecks，可检查生产视频播放器的默认调度、真实快进/快退、播放状态及跳转后的时钟继续推进，默认使用项目视频样本；`FALLERY_SEEK_SAMPLE` 可指定实际文件。所有播放器保持静音/零音量，样本不携带版本信息以避免写入用户续播记录。时钟推进仍不能证明视频帧已呈现。

关键帧索引检查：`dotnet run --project Tests/CoreChecks/CoreChecks.csproj -- . --keyframe-sample <MP4视频完整路径>`。只读取系统索引，覆盖取消、不支持/缺失文件、吸附方向、首尾与最大偏差；无播放、无外部程序依赖。ExperienceChecks 同时验证真实进度条走关键帧路径，续播等准确 Position 路径保持原目标。按微软 [IMFSeekInfo 文档](https://learn.microsoft.com/windows/win32/api/mfidl/nf-mfidl-imfseekinfo-getnearestkeyframes)，关键帧定位用于减少前置解码，但不保证屏幕呈现时延。

低延迟模式仅保留为诊断对照，生产应用已撤回；SeekCompleted 更快不等于视觉效果更好。该模式面向实时场景且可能增加资源使用与功耗。[Microsoft 文档](https://learn.microsoft.com/windows/apps/design/controls/media-playback#enable-low-latency-playback)

实际窗口诊断：启动时将 `FALLERY_PLAYBACK_TRACE` 设为已存在目录下的日志文件完整路径。异步有界队列记录按键、播放器调用、缓冲和跳转后八秒的时钟；不记录媒体路径/内容，普通启动默认关闭。比较前跳未播放位置与后跳已播放位置，并由用户确认声音、画面及按钮响应。

ExperienceChecks 增加生产处理方法检查：播放/暂停时反复侧键跳转，随后模拟到达单击/双击处理方法，验证不改变播放或全屏状态；覆盖中键/右键、左键单击、双击状态补偿和触摸。设置 `FALLERY_VIDEO_GESTURE_CHECKS=1` 可单独运行。使用静音假播放器，不注入用户输入；隐藏宿主无法安全进入系统全屏，沿用已有测试方式建立全屏标记并验证退出路径。

人工验收：视频播放中和暂停时，在画面上连续按鼠标两侧键，确认向前/后约 5 秒、就近关键帧最多偏差 3 秒且保留播放状态；点击尚未播放的后半段，检查图像是否迅速恢复、声音同步；进入全屏后再试。左键单击仍暂停/播放，只有左键双击切换全屏；右键和中键不触发这两个动作。

## 音频验收

打开含 MP3、WAV、FLAC 或 M4A 的目录，确认音频卡片、计数、“仅音频”筛选和文件夹入口；双击音频后检查封面/音符、播放暂停、拖动进度、音量、倍速、上一项/下一项和连播。详情仅显示实际存在的标题、艺术家、专辑、时长等。返回图片/视频后缩放、旋转等操作应恢复，音频本身不显示逐帧、截图和旋转。搜索支持 `type:audio`，旧索引需完成刷新后才包含新增的音频类型；已注册的打开方式需重新注册以添加音频扩展名。

自动检查只播放生成的全零 PCM WAV，并从播放器创建起保持静音和零音量；验证真实播放器状态、跳转、倍速、相邻音频连播、关闭释放及卡片复用，不验证用户音箱的听感。实际解码取决于系统编解码器，不内置新解码器。

## 从资源管理器粘贴

资源管理器中选择若干测试文件及文件夹，Ctrl+C 后到 Fallery 目标目录 Ctrl+V（或空白处右键“粘贴”），确认来源保留；改用 Ctrl+X 后粘贴，确认完整成功时来源移走。再验证同名文件的替换/跳过/保留两者/取消，以及文件树所选目录作为粘贴目标。文本输入框仍使用文本粘贴。粘贴中若复制了其他内容，新的剪贴板不能被清除。

核心检查用独立 HGLOBAL 模拟原生 CF_HDROP 和 Preferred DropEffect，覆盖 64 文件加文件夹、Unicode/ANSI、长路径以及实际样本复制移动，不调用系统 SetClipboardData 或 EmptyClipboard，不改用户剪贴板。资源管理器与应用窗口之间的实际操作留给人工验收。

## 文件树时间显示

设置分为常规、文件夹、应用三个标签。侧栏独立排除按钮应直接打开文件夹标签；确认默认 59 条名称规则已勾选，取消一条或添加新名称后点“完成”，当前浏览结果随之刷新；再打开设置、重启应保留。点“取消”或 Esc 不应保存排除草稿；“恢复默认名称”只重置名称规则，不取消手动路径排除。具体路径通过文件夹右键添加，在文件夹标签中取消排除，仍只影响文件树和收藏。搜索索引需手动刷新。

CoreChecks 覆盖旧设置默认迁移、显式清空、名称验证/去重、真实扫描及持久化；隐藏语言窗口检查覆盖三个固定标签、中英文宽度一致、默认选中项和草稿不提前生效。实际菜单、滚动与保存/取消操作仍由用户验收。

点击文件树上方的时间按钮，在“不显示 / 修改时间 / 创建时间”间切换；对照资源管理器同一目录的属性。检查收藏、已展开节点以及随后展开的新节点均显示所选时间，原有排序、当前选择和展开状态不变；关闭再启动应保留选择。旧版本已开启显示的设置应继续显示修改时间。

## 文件树上级目录吸顶

展开“桌面”或包含大量子目录的分支并向下滚动，上级目录应固定在文件树顶部。点击吸顶行箭头应收起对应分支并显示真实父行，右侧浏览目录保持不变；点击名称仍进入目录。检查多层嵌套（最多固定最近三级）、跨分支滚动、返回顶部、在吸顶行上滚轮，以及修改/创建时间与明暗主题。隐藏窗口检查直接滚动隔离模型并验证节点与容器数量，不向用户窗口发送鼠标输入。
